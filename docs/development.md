# Development

How to run REXCHESS while you work on it, how to test it, and what to do when something is off. To just try it,
the [README](../README.md) has the one command you need.

## What you need

| | For |
|---|---|
| Docker | The easiest way to run everything, and the database in any case |
| JDK 17 | The backend (the project targets Java 17; a different JDK fails with "release version 17 not supported") |
| Maven 3.9 | Building and testing the backend |
| Node 20 and npm | The frontend |
| Chrome | The frontend specs run in headless Chrome |
| Python 3.10+ | Only for [training the network](../training/README.md) |

## Everything in Docker

```bash
docker compose -f docker-compose.dev.yml up
```

Starts PostgreSQL, the backend (`mvn spring-boot:run` in a Maven container, with Spring DevTools restarting it when
classes change) and the frontend (`npm install`, then `ng serve` with a file poll). Your source folders are mounted, so
edits show up without rebuilding. Open <http://localhost:4200>.

Stop it with `Ctrl+C`; `docker compose -f docker-compose.dev.yml down` removes the containers and keeps the database.

## Running the parts yourself

Faster to iterate on, and what you want for debugging. Start only the database in Docker:

```bash
docker compose -f docker-compose.dev.yml up -d db       # PostgreSQL on localhost:5432
```

**Backend** (port 8080):

```bash
cd chess-engine
export JWT_SECRET=dev-only-jwt-secret-do-not-use-in-production-0123456789      # PowerShell: $env:JWT_SECRET = "..."
mvn spring-boot:run
```

`JWT_SECRET` is required (at least 32 bytes) and has no default. The database settings default to the dev database
(`chess_db`, user `chess_user`, password `chess_pass`), so nothing else is needed. Flyway creates the schema on first start.
The API explorer is at <http://localhost:8080/swagger-ui.html>.

**Frontend** (port 4200):

```bash
cd frontend
npm ci
npm start
```

`ng serve` forwards `/api` and `/ws` according to [`frontend/proxy.conf.json`](../frontend/proxy.conf.json), which points at
`backend:8080`, the host name Docker gives the backend. Outside Docker, give it a proxy file that points at localhost
instead and pass it on the command line (keep it out of git):

```json
{
  "/api": { "target": "http://localhost:8080", "secure": false },
  "/ws":  { "target": "ws://localhost:8080", "secure": false, "ws": true }
}
```

```bash
npx ng serve --proxy-config proxy.local.json
```

## Configuration

Spring reads these from the environment (`SPRING_DATASOURCE_URL`) or from `application.yml` (`spring.datasource.url`).

| Setting | Default | Meaning |
|---|---|---|
| `JWT_SECRET` | none, required | Signs login tokens. `openssl rand -base64 48` |
| `ALLOWED_ORIGINS` | `http://localhost:[*]`, `http://127.0.0.1:[*]` | Browser origins allowed to call the API and open WebSockets, comma separated |
| `SPRING_DATASOURCE_URL`, `_USERNAME`, `_PASSWORD` | the dev database | Where PostgreSQL is |
| `SPRING_PROFILES_ACTIVE` | none | `prod` turns off SQL logging, tightens Flyway, and sets the log level to INFO |
| `jwt.access-token-expiry-ms`, `jwt.refresh-token-expiry-ms` | 900000, 604800000 | 15 minutes, 7 days |
| `app.abandon-timeout-seconds` | 60 | How long a player may be away from an online game before they lose it |
| `app.first-move-timeout-seconds` | 30 | An online game with no first move by then is called off, unrated |
| `app.rate-limit.auth-per-minute` | 20 | Login and registration attempts per address per minute, each counted separately |
| `app.recover-games-on-startup` | `true` | Bring back online games that were active when the server stopped |
| `app.engine.eval` | `nnue` | The AI's evaluation: `nnue` or `classical` |
| `app.engine.nnue-file` | the bundled network | Path to another `.nnue` file |

The production variables (`SITE_ADDRESS`, `POSTGRES_PASSWORD`, `JWT_SECRET`) are described in
[`.env.example`](../.env.example) and [DEPLOY.md](DEPLOY.md).

## Tests

**Backend.** The tests boot the real Spring application and talk to PostgreSQL, so the dev database must be running:

```bash
cd chess-engine
mvn -B -ntp verify
```

The test run supplies its own `JWT_SECRET`, turns off game recovery at startup (the dev database keeps games from earlier
runs, and bringing them back would change ratings in the middle of a test), and loosens the login rate limit. A coverage
report is written to `target/site/jacoco/index.html`.

The engine's tests do not need a database and include checks against independent references:

* perft node counts for well-known positions, for move generation;
* CSV fixtures in `src/test/resources/engine/` computed by python-chess (legal moves, Polyglot hashes, forced mates),
  regenerated by `training/engine_fixtures.py`;
* the integer network arithmetic against a separate Python implementation (`src/test/resources/nnue/`,
  regenerated by `training/nnue_fixtures.py` and `training/golden.py`).

**Frontend.**

```bash
cd frontend
npm run test:ci                                 # once, in headless Chrome (what CI runs)
npm test                                        # watch mode, in a browser window
npm run build -- --configuration production     # also type-checks the templates, which the specs don't
```

The production build enforces size budgets: 1 MB for the initial bundle and 20 kB for any component's stylesheet. A
component whose styles outgrow that should be split, or its shared parts moved into `src/styles.scss`.

**CI** ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) runs the backend job (Java 17, a PostgreSQL service) and
the frontend job (tests, then the production build) on every push to `main` and every pull request. A passing run on
`main` triggers [`deploy.yml`](../.github/workflows/deploy.yml).

## Changing the database

Add a new file to `chess-engine/src/main/resources/db/migration/` named `V9__what_it_does.sql` (the next number). Never
edit a migration that has been applied anywhere: Flyway checks their checksums and refuses to start. Hibernate only
validates the schema (`ddl-auto: validate`), so an entity that does not match the tables fails at startup, which is
the point.

## The engine on its own

The AI is a UCI engine that any chess GUI can play, and that `training/match.py` pits against others.

```bash
mvn -f chess-engine/pom.xml -DskipTests compile
sh tools/engine/rexchess-uci.sh       # tools\engine\rexchess-uci.cmd on Windows; set JAVA_HOME to JDK 17
```

Then type UCI commands: `uci`, `isready`, `position startpos moves e2e4`, `go movetime 1000`; `eval` prints the static score
of the current position. `bench 8` searches a fixed set of
31 positions and prints the node count and speed: the count changes whenever the search changes, so it is the engine's
signature. Options: `Hash` (MB), `MultiPV`, `Level` (0 for full strength, 1 to 6 for the difficulty levels), `Eval`
(`nnue` or `classical`) and `EvalFile`.

How the engine works and how it was trained: [how-the-ai-works.md](how-the-ai-works.md), [training/README.md](../training/README.md).

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `release version 17 not supported` from Maven | `JAVA_HOME` points to an older JDK. Point it at a JDK 17 |
| The backend refuses to start, mentioning the JWT secret | `JWT_SECRET` is not set, or shorter than 32 bytes |
| `Connection refused` to `localhost:5432` | The database container is not running: `docker compose -f docker-compose.dev.yml up -d db` |
| The frontend shows errors for every request, or `ECONNREFUSED backend` in the terminal | `ng serve` is using the Docker proxy file. Use a proxy file that targets localhost, as above |
| Login or WebSocket calls fail with `403` from a browser | The page's origin is not in `ALLOWED_ORIGINS` |
| Maven reports success but the code does not compile in the IDE (or the reverse) | The IDE's Java language server compiles into `chess-engine/target/` and tolerates errors, so Maven can say "Nothing to compile". Run `mvn clean verify` for the real answer |
| Ratings or games change by themselves after starting the backend | The dev database keeps games from earlier sessions, and the server resumes any online game that was active. Their clocks and abandonment countdowns then play out. Reset with `docker compose -f docker-compose.dev.yml down -v`, which **deletes the dev database** |
| An online game is called off after 30 seconds | By design: nobody made a first move (`app.first-move-timeout-seconds`). Move faster, or raise it while testing |
| `Killed` or exit code 137 while building a Docker image | The machine ran out of memory: give Docker more, or add swap on a server |
